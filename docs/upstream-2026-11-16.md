  adapter; new Metal copy kernels in `speculative/cache_kernels.py` commit
  short speculative prefixes, used by `ArraysCache` (the gated-delta state of
  Qwen3.8's linear-attention layers) and by the rotating-cache commit. DFlash2
  gains `draft_batch` and `no_rope_layers`; `dflash.py` prefers a
  `draft_batch_greedy` when the drafter offers one.

  `PREFILL_STEP_SIZE` as its default; our scripts use `PREFILL_STEP` and pass

### The admission threshold moved down to 32k

With the default reserve 1.5 the **cold 32k request** was answered with
`APCAdmissionError` ("cannot fit the APC prefill memory budget even alone",
raised in `generate/ar.py: _prefill_step`), 0.2 s after it was queued. On
11-06 the same request passed (22.4 s) and only 96k was rejected. `apc.py` and
`generate/ar.py` are byte-identical between `0.7.12` and `0.8.0`, so this is
not a code change: the budget is derived from the memory free at that moment,
and the machine was tighter today (swap 11.3 GB used of 12 GB, a VM with
1.5 GB RSS and Safari running; `mem active=33.5 GiB`, 85 % of the 40 GiB
working set, before the request). The follow-up turn 0.2 s later was admitted
and prefilled cold (cached 40). With `APC_RESERVE_GB=0.5` both contexts pass
as exact hits (restored 8,044 / 32,044, peak 36.5 GiB).

**Still Tom's call (open since 11-06), now more pressing:** lower the Kolibri
default to 0.5, or cap the context, or patch the admission error into a cold
prefill without APC. On today's memory state the production default fails at
32k, not at 96k.
