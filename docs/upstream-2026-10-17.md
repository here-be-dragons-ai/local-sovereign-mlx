## Why a commit

- **`#2525`**: a finished `SpeculativeGenerationBatch` kept its prompt cache,
  hidden state and rounds generator installed until the next request's
  prefill completed. With DFlash 2 at 28k tokens the process peak here went
  27.4 → 25.5 GiB (table below).
- **`#2510`**: Qwen3.5 ragged decode attention called `mx.contiguous` on K/V
  and copied every full-attention layer's cache per step (B > 1).
- **`#2527`**: mlx 0.32.4 sums the affine-quantization bias term in float32;
  the fused 4/5-bit projections did not, so their outputs drifted from the
  unfused path. **The `v0.7.8` tag with mlx 0.32.4 fails 111 upstream tests**
  (`test_fused_projection_parity`, `test_quantized_moe_hyperconnection`,
  `test_wide_quantized_verifier`; the same 111 with and without our patches).
  With mlx 0.32.3 all 484 speculative tests pass. main has the fix and requires
  `mlx>=0.32.4`, so tag and mlx version must not be mixed.

Also in, from the 0.7.5–0.7.8 releases: `#2498` (tool-schema keys sorted
before rendering, so equivalent tool lists hit the same APC prefix), `#2442`
(packed gated-delta kernel for Qwen3.5 prefill), `#2273` (cancellation during
multi-row prefill), `#2423` (Kolibri 1), `#2457` (bundled drafters load
directly). New dependency: `datasets` (from `#1939`), which pulls pandas and
pyarrow; `uv pip check` clean.

Pinned as a git requirement **inside** `PINS` together with `mlx==0.32.4`, so
uv resolves both at once. The commit reports `0.7.8`, like the tag:
`install-prereqs.sh --check` and the start banner append `(git b8bf04c)`.

kernel by default — from `qL >= 1024` only. Probe, 24/4 heads, kL 22,747,
bf16, transient beyond the output:

|---|---|---|---|

### 0036, new: a per-step sync from #2273

`#2273` added `int(fa_cache.offset[0].item()) >= 0` to the qwen3_5 single-row
shortcut, so a still-left-padded row does not take it. The check runs every
decode step; `offset` is advanced lazily each step, so `.item()` waits for the
previous step's forward. That shortcut is what an exact-APC warm hit decodes
through without a drafter. Found as a warm/cold ratio of 0.954 (table below);
removing the check as an experiment gave 0.988, which pinned it down.

`0036` computes the same predicate from `_idx` (a Python int) and
`left_padding` (changes only on prepare/filter/finalize): `BatchKVCache`
keeps `offset == _idx - left_padding` through every mutation, and so does
`0035`'s write-back. Equal to the original over 100 steps with left padding
0/1/5/17, through `trim` and `filter`; other cache types keep `.item()`. It
anchors on the function `0035` adds.

## Kolibri 1

- Server: mlx-vlm's `kolibri1` (`#2423`, unchanged since its merge). Logits of
  `Kolibri-1-MLX-3bit` on three prompts against our implementation, both on mlx
  0.32.4: **bit-identical** (max |diff| 0.0).
- Our implementation moved from patch `0050` to `kolibri1/` in this
  repository. `convert-kolibri.py`'s `use_local_kolibri1()` registers it as
  `mlx_vlm.models.kolibri1` for its own process; `measure-quality.py` calls it
  for every `kolibri1` checkpoint, so the quality tools keep the code their
  numbers were measured with. Needed because upstream's `sanitize` does not
  dequantize the FP8 release (`weight_scale_inv`) and names the experts
  `mlp.switch_mlp` / the bias `mlp.gate.e_score_correction_bias`, while
  `convert-kolibri.py`'s predicate and `gptq-kolibri.py`,
  `diagnose-kolibri-layers.py`, `kolibri-down4-candidate.py` use
  `mlp.experts` / `mlp.expert_bias` / `use_sliding`. With upstream's module
  the converter would have quantized the experts at 6 bits instead of 3,
  without an error.
- FP8 release, lazy load through `measure-quality.load_lazy`: our module
  loaded, layer 0 `q_proj` bf16, mean |w| 4.7501e-4 — equal to an
  independent numpy E4M3 × block-scale decode from the safetensors bytes.
