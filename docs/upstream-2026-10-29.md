## Warm decode without a drafter

`./measure-apc-warm-decode.py --prompt-tokens 28000 --max-tokens 300
--repeat 2`, 28,035 tokens, f16 KV, APC exact, `roomy`, fresh `STATE_DIR`,
one server per arm, AC power, embed/rerank servers idle alongside.

| arm | cold t/s | warm t/s | warm/cold |
|---|---:|---:|---:|
| 0.7.11 + seven patches | 15.32 / 15.48 | 14.86 / 14.90 | **0.966** |
| same, `h.shape[1] > 1` removed, + `0035` + `0036` | 15.32 / 15.49 | 15.57 / 15.69 | **1.015** |
| 0.7.11 + seven patches, repeat | 15.60 / 15.64 | 15.05 / 15.09 | 0.965 |
| same, `--phases`, `MEM_PROBE_INTERVAL=0.5` | 15.51 / 15.64 | 15.09 / 15.06 | 0.968 |
| 10-17 reference: main + `0036` | 15.97 / 16.06 | 16.01 / 16.05 | 1.001 |

Memory (`--phases` run): decode sum warm 22.50 / 22.50 GiB, cold
22.48 / 22.48 GiB; prefill peak cold 24.82 / 24.87 GiB. No warm spike -- the
30 GiB excursions `0035` once removed (`#2210`) do not come back.

So the old patches still buy ~5% warm decode, but only by undoing
`08d552a2`, and that variant fails its new test
`test_qwen3_5_single_row_decode_retains_batch_cache` (6 cases): logits match,
but the shortcut replaces the cache objects each step, which the test pins
and the 0.7.11 compaction/checkpoint code may rely on. **Decision: retire
`0035`/`0036`, accept warm/cold ~0.97.** The remaining gap is in the batch
decode path itself; not traced. With a drafter the shortcut was never taken,
so the default profile is unaffected.
