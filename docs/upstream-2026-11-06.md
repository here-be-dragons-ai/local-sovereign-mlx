## Regression: Kolibri follow-up at 96k is rejected

On 0.7.4 the 96k follow-up missed the snapshot and was prefilled cold (112 s,
`docs/kolibri-quality/ttft-2026-10-08.jsonl`). On 0.7.12 with the default
reserve 1.5 the server answers it with an error: *"The request cannot fit the
APC prefill memory budget even alone. Reduce the context length or memory
reserve."* The client gets no answer at all. With reserve 4 the same happens
to a cold 64k request.

`APC_RESERVE_GB=0.5` lets the 96k follow-up through as an exact hit (1.6 s).
Swap rose from 5.4 to 5.9 GB during that run (it was already high before).
Qwen3.8 at 60k with its auto reserve is not affected.

**Open, Tom's call:** lower the Kolibri default to 0.5, or keep 1.5 and cap
the Kolibri context below 96k, or patch the admission error into a cold
prefill without APC.

## Side note: the disk ran full

Each measurement server with a fresh `STATE_DIR` opens its own APC disk tier
(Kolibri cap 40 GB). With ~20 GiB free, five such directories (~16 GB) filled
the data volume during the 96k run; deleted. Measurement runs now use
`APC_DISK_MAX_GB=4` and delete their `STATE_DIR` right after. An empty
`APC_DISK=` does not disable the tier (`${APC_DISK:-...}` treats empty as
unset).
